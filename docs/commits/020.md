# Overview del incremento 020 — Usuarios: búsqueda, filtro por rol y edición de clientes

Fecha: 2026-11-11. Rama prevista: `feature-usuarios-busqueda`. Mensaje propuesto: `feat: add user search, role filter and customer contact editing`.
Estado: **en revisión** (código, pruebas y documentación listos; pendiente de tu revisión antes de confirmar, tarea C20-12). La API sigue en **53 operaciones** (cambian parámetros y reglas; no hay migración).

## Resultado

| Área                | Cambio                                                                                                                                                                                                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Listado de usuarios | `GET /users` acepta `search` (usuario, nombre, teléfono y correo del cliente; con 3 o más dígitos también los dígitos del teléfono) y `role` (uno o varios separados por coma; `admin,operador,repartidor` = «personal»). Sin parámetros la respuesta es la de siempre. |
| Edición de clientes | `PATCH /users/:id` sobre un cliente guarda `fullName` (2 a 100) y `phone` en su ficha, en una transacción. El correo no se acepta y su `username` es interno (`400`). Restablecer su contraseña sigue permitido.                                                        |
| Personal            | El nombre sigue limitándose a 80 caracteres (verificado en el servicio; el DTO admite 100).                                                                                                                                                                             |
| Rol                 | Un admin no cambia su propio rol (`409`). Cambiar el rol de otro usuario **revoca todas sus sesiones**: vuelve al login y sus canales en vivo se cierran en el siguiente latido (máx. 25 s).                                                                            |
| Borrado             | El `409` por historial dice «El usuario tiene historial asociado; no se puede eliminar.» y cubre movimientos, pedidos, rondas y encuestas (con una prueba por tipo).                                                                                                    |
| Código compartido   | `escapeLike` pasa a `src/common/like.ts`.                                                                                                                                                                                                                               |
| Fuera de alcance    | Desactivar usuarios, `mustChangePassword`, búsqueda sin tildes (`unaccent`/`pg_trgm`) y editar el correo del cliente.                                                                                                                                                   |
